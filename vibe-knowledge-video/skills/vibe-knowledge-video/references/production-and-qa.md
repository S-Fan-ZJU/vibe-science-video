# 可复现制作、验收与局部修复

用于工程初始化、质量样段、正式渲染、最终文件验证和时间点修订。新片先完成 [用途与风格确认](style-and-purpose.md)；可用工具见 [tools.md](tools.md)，逐项记录见 [QA 模板](../templates/qa-checklist.md)。

## 1. 目录与版本先建立清楚

新项目建议采用以下结构，已有工程优先沿用清楚的原结构：

```text
project/
  AGENTS.md              新对话的项目入口
  README.md
  sources/               原文索引、事实表、来源记录
  planning/              brief、项目状态、分镜、素材方案
  references/            本片参考入口、来源与拆解记录
  docs/                  其他制作说明
  film/                  可编辑动画工程与必要素材
  audio/                 原音轨、剪辑 BGM、最终混音
  output/
    v01/                 样段、时间轴、QA
    v02/                 正式成片、字幕、交付清单、QA
    covers/              各比例封面与提示词
    publishing/          标题、简介、标签
  tmp/                   可重建的中间文件
```

旧成片、旧源码与用户满意镜头不覆盖。每个交付版本记录：代码版本或快照、关键依赖版本、音频 hash、时间轴 hash、输出规格、文件 hash、QA 范围。临时补片和试验文件不要与最终完整视频混在同一个“final”名称下。

继续项目时先读根目录指引、`planning/brief.md` 与 `planning/project-state.md`，再按最新交付清单确认正式版本；已有工程采用其他路径时沿用其明确索引。历史计划可能比最终脚本长，旧说明可能只对应 15 秒样片；不要直接照抄。每次重要交付或用户方向变化后更新状态，区分已确认要求、已实现待评价和建议未实现。

## 2. 先做最低成本的环境验证

检查现有工程、锁定依赖、可用 Node／Python、磁盘空间、字体、浏览器渲染能力和音视频工具。现有可运行工程无需为“跟上最新版”整体升级。新项目锁定实际安装版本，保存锁文件；官方 API 用当前版本文档核对。

中文字体必须在实际渲染环境可取得。只在本机安装的字体可能在他人机器消失；按许可打包可分发字体，或提供明确安装步骤和后备字体。不要从用户系统目录随意复制字体到公开仓库。

先跑几秒样段，确认中文、资源、透明层、音轨和编码都正常，再开始几分钟的高分辨率渲染。用项目内临时目录，观察磁盘消耗。不要因为本机有 GPU 就声称无头渲染器正在使用它，应读取或实测后端。

## 3. 所有状态由时间决定

核心动画由帧号和帧率计算，直接跳到同一帧应得到同一结果。不要依赖播放历史、真实时钟、上一帧累加位置、未固定随机数或未等待完成的资源加载。

统一时间轴应为字幕、主动作、SFX 和章节提供数据源。脚本、SRT、cue 表从同一份数据生成，避免修改画面后文档仍指向旧时刻。

时间区间采用一种明确约定。本包模板使用帧区间 `[start_frame, end_frame)`，结束帧不包含在内；与某些渲染器的“最后一帧包含”参数转换时要减一。帧率可配置，不固定为 60。

共享材质和几何适合缓存，但局部状态必须隔离。一个物体受损变暗不应让整个场景所有复用材质都变暗。资源释放与复用也要保持确定性。

## 4. 样段必须覆盖真正困难的部分

按片长和实际难点选择检查窗口，通常覆盖：

| 样段 | 解决什么问题 |
|---|---|
| 开场（可从前约 15 秒起） | 观看任务是否明确，文字和主体能否读懂，风格与声音是否符合本片用途 |
| 最难解释动作 | 空间动作、条件比较、路线、图表推导或样本筛选能否准确完成 |
| 一次代表转场 | 前后语义、遮挡、场景交换、构图恢复是否连贯 |

长度按任务调整，窗口可以合并。它们应使用正式资产、材质、灯光与本片声音方案；低质量占位样片无法验证完成度。用户要求只交样片时到此交付，用户授权全片则内部检查通过后继续。科研稳定图解、无 BGM 教学和娱乐化强拍点均按各自 brief 检查，不把更闪、更艳等同于更好。

## 5. 渲染时控制资源，而不是盲目加并行

提高并发会增加浏览器、3D 上下文和编码器的内存压力。先观察短片的每帧耗时和峰值内存，选择稳定并发，再扩大范围。估算渲染时间可用已测每帧耗时，但注明只是估算。

遇到慢或失败，依次看：

1. 资源是否在反复加载或重新生成。
2. 是否落入软件渲染，目标 GPU 后端是否真的有效。
3. 透明重叠、细分网格、粒子数量是否过量。
4. 并发与内存、磁盘是否相互挤压。
5. 是否把编码瓶颈误判为场景渲染瓶颈。

GPU 画面渲染和视频编码是两个阶段，前者用 GPU 不代表后者也用 GPU。后端或编码方式改变后，重点比较材质、颜色、透明层和最终 MP4，而不只看速度。

## 6. 各层验收分别证明不同事情

| 层次 | 必查内容 | 不能替代的检查 |
|---|---|---|
| 用途与风格 | 受众、知识深度、色彩、节奏、声音与闪烁是否符合已确认 brief | 其他参考的风格不能替代本片选择 |
| 内容 | 事实、因果、角色、条件、标题承诺 | 画面漂亮不能替代事实核对 |
| 文件 | 完整解码、帧数、fps、尺寸、时长、音轨、时间戳 | 能解码不表示观众看得懂 |
| 时间 | 主结果帧、音频瞬态、编码音轨对齐 | 音频偏移小不表示主动作有冲击 |
| 空间 | 全程间隙、透明排序、相机遮挡 | 一张静帧不代表整段动作无穿模 |
| 观看 | 最终 MP4 选帧与连续播放、手机尺寸阅读 | Studio 或 PNG 不代表编码结果 |
| 听感 | 完整混音、实际设备、相同音量 A/B | 峰值合格不代表音效足够清楚 |

文件层建议检查：声明规格与实际一致；帧数与时间轴一致；完整解码无错误；时间戳合理连续；本片需要音轨时，音轨存在且长度符合预期；前后无意外黑帧或静音。明确选择无声音时，音频项标记不适用并写明 brief 依据。工具输出必须读取，不只看进程退出成功。

## 7. 选帧与短片怎么选

每章至少覆盖入场、中段、关键动作前后、转场前后。主爆点看结果帧及相邻帧；窄间隙运动看完整动作；音乐接缝与视频补片边界看前后连续短片。

从**最终编码 MP4**抽帧，检查主体亮度、文字、透明层、图像锐度、帧间闪烁。再在小窗口看字幕；缩小后的可读性比仅看 4K 大图更接近实际使用。

抽帧不等于完整播放。报告可写“检查了 12 个时间点、3 个动作片段、完整解码通过”，不要扩写成“已逐帧观看全片”。最终整片实时观看和设备试听未做时保持待检查状态。

## 8. 修订：先定位，再选最小可靠范围

使用 [修订模板](../templates/revision-request.md) 记录版本、时间、对象、实际现象、目标和需要保留的部分。

| 改动 | 优先考虑 | 必须复核 |
|---|---|---|
| 只改同长度混音 | 视频流复制，重编码音频后封装 | 音频时长、起点、事件、完整解码 |
| 局部几何／文字／动画 | 补渲受影响范围与必要余量 | 区间帧数、边界连续、颜色、声音保持 |
| 全局时间轴／相机／画幅 | 较大范围或全片重渲 | 全片节奏、字幕、资产裁切、QA 更新 |
| 封面／简介 | 独立更新发布资产 | 内容承诺和实际尺寸 |

局部补渲不是“随便剪两刀”。如果要复制原视频码流拼接，应确认可独立解码的关键帧边界、编码参数、尺寸、fps、时基、色彩与音轨安排兼容，并检查 PTS／DTS、完整解码、漏帧／重帧和接缝像素。普通按秒裁剪不能保证这些条件。

不具备可靠码流检查工具时，优先用标准时间轴重新编码所需版本，或重渲适当范围，不应假装无损拼接已经验证。

## 9. 渲染异常的排查顺序

先保存问题片段与源码身份，再在相同帧比较：场景预览、静帧、短片、正式渲染中间帧、最终编码帧。控制变量，每次只改变有依据的一项。

- 几何穿透：先查世界坐标和完整模型范围，再调镜头。
- 透明反转：先判断是否实际相交，再处理深度与排序。
- 亮度异常：查主体和背景是否同时受影响、颜色设置与资源状态，不能直接全片提亮。
- 字体丢失：确认实际运行环境字体加载完成，检查后备字体和排版变化。
- 音乐错位：先比输入 hash 和最终音轨，再查编码延迟、裁剪与时间零点。

没有复现的原因应写成未确定，不把猜测写成修复结论。修正版输出正常可以交付，但应保留已检查范围与尚不确定的原因。

## 10. 交付清单必须能让下一位继续

交付说明包含：本片已确认的用途与风格；当前正式视频位置、规格、版本；可编辑工程和启动方法；实际渲染命令或已验证入口；最终脚本与字幕；音乐和素材来源（无声音时标明）；cue 与混音记录；任务范围内的封面和文案；QA 证据；已知问题；旧版本位置。根目录指引和状态文档应能定位以上内容，以及本片采用／不采用的参考方法。

给发布者清楚区分“完整成片”“局部补片”“诊断短片”“旧版本”。输出名称可以带版本，不用含糊的 `final-final-new2`。

在公开下载包里不放私人绝对路径、账号令牌、未授权的论文全文、缓存、node_modules 或临时渲染帧。可再生成的资产提供生成或下载方法。平台发布是单独的外部动作，只在用户明确授权的范围执行。
