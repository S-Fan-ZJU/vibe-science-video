# Vibe Knowledge video

把知识做成适合本次用途、能看懂关系、经得起实际播放的动画。沿用 Vibe Science Video 已实践的制作、工具与验收流程，扩展到不同领域和风格。知识深度、配色、声音和动效分别选择；科研表达与娱乐化参考都是可选方向。不要承诺任意主题都能一次生成成功，也不要把生成源代码当成已经交付视频。

## 每条新视频先确认用途与风格

这是本 skill 的开工步骤。先读 [用途与风格](references/style-and-purpose.md)，整理本次已给出的信息，再用 2–3 个简短问题补齐：

1. **用途与受众：** 用在哪里、给谁看、知识基础怎样、看完应理解什么？
2. **风格与参考：** 科研／教学、大众科普、娱乐传播还是混合？参考中哪些特征采用，哪些不采用？
3. **节奏与声音：** 舒缓／适中／紧凑？音乐、旁白和音效的存在感？卡点及音乐闪烁关闭、轻微还是明显？

本次已明确的信息直接记录，仅问缺项；用户明确委托自行选择时记录依据。用途或风格仍缺失时，等待回答后再定分镜、视觉、配乐并制作，可以先整理资料和核验事实。不要仅因题材、平台或上一条视频就自动套用风格；同一影片的普通修订沿用已确认方向。

将答案、确认来源和待定项写入 [brief](templates/brief.md)。所有风格均保持事实准确、因果清楚与来源可追溯。鲜明颜色也能用于科研图解，克制镜头也能搭配节奏音乐；允许无 BGM、关闭闪烁、旁白主导与二维表达。具体评价以本片用途为准，不以更鲜艳、更多特效作为统一质量标准。

## 先判断任务处于哪里

- **新作**：读取 [故事与证据](references/story-and-evidence.md)、[视觉设计](references/visual-direction.md)，建立 brief、事实表和分镜。
- **接着做已有项目**：先读项目 `AGENTS.md`、`planning/brief.md`、`planning/project-state.md` 和参考分析索引；已有项目路径不同则沿用真实入口。找到正式版、最终音轨、时间轴及用户最后反馈，保留旧输出，不用历史草案覆盖正式版。
- **拆解参考视频**：读 [参考分析与迁移](references/reference-analysis.md)，记录源片、时间段、证据、适用用途和迁移方法；区分已学到的方法与已实现的通用组件。
- **修改指定问题**：读取 [制作、检查与修复](references/production-and-qa.md) 的修复部分，记录时间点、对象、现象，决定换音轨、补渲还是重排全片。
- **只做封面或文案**：读取 [发布素材](references/publishing.md)，不启动不必要的视频重做。

制作新片、重新定视觉或增换素材时，检查项目已有参考、图像、数据与模型。需要三维候选时读取 `assets/models/README.md`、`inventory.json` 和已有预览；没有清单时用 [模型复用流程](references/model-library.md) 中的只读盘点工具找真实文件。按题材对象、镜头与已确认风格选择，在 [素材方案](templates/asset-plan.md) 记录文件和取舍。仅改字幕、混音或发布文案时，无需重扫模型库。

声音、受众、时长与画幅按本片确认。16:9、4K60 母版＋1080p60 播放版是已有经验中的可选交付规格；预览可用较低分辨率。预算、硬件或题材不适合时提出具体取舍，不把 4K、60 fps 或 3D 当成质量的替代物。

只补问无法从现有资料取得、且会改变结果的信息。已有主题就不要强制重新选题。用户要求先看样片时，在样片处交付；用户授权连续完成时，经过内部质量检查继续做完，不逐阶段重复请求许可。制作授权不自动包含公开发布或修改外部账号。

## 这套流程的核心约束

1. **第一眼就有意义。** 首帧有主题相关主体；科研片可直接给研究问题，教学片呈现待理解关系，大众传播可用人的处境或反直觉矛盾引入。
2. **每段推进一个理解。** 以“问题 → 条件变化 → 对象行为 → 可见结果”解释机制；回答之后再引出下一问。不能用一串疑问替代答案。
3. **事实与比喻分开。** 记录对象、条件、因果、出处、解释分歧和画面简化；科学研究不拼成万能系统，历史事件不混淆时间与因果，数学图形与数据共用模型。参考作者的说法需要独立核查。
4. **声画响应按选择启用。** 可选持续能量、普通拍点和关键揭晓三级，各层可关闭。需要卡点时，让声音攻击点对应可见结果，准备动作提前安排；不强迫每个拍点闪光。
5. **紧凑不等于删字。** 先去掉慢入场和读完后的空等；复杂动作仍需观察时间。字幕、动作、SFX 从同一时间轴导出。
6. **精致服务于理解。** 清晰主体、材质、层次、方向和可见接触优先于无关粒子。需要前后遮挡、插入、包裹的机制，应使用可验证的空间结构。
7. **转场也是分镜。** 明确上一场对象、遮挡或形状接续、交换帧、下一场落点。不要等全片完成后统一加淡入淡出。
8. **检查最终文件。** Studio、PNG、编码 MP4 和上传预览可能不同。完整解码、选帧检查、连续播放与实际试听分别记录，不能相互冒充。

## 可执行的交付流程

下表用于完整新片。用户只要分镜、参考分析、封面或局部修订时，按对应范围执行和交付，不补做无关阶段；无声音方案不强加音乐步骤。

| 阶段 | 必须产生的可检查成果 | 下一步的判断依据 |
|---|---|---|
| 1. 接收输入 | [brief](templates/brief.md)：用途、受众、风格、节奏／声画、资料、规格、交付范围 | 关键方向有确认依据；待定项和观看目标明确 |
| 2. 内容与叙事 | [事实表](templates/fact-ledger.md)、一句话主线、问题链、前 15 秒设计 | 关键结论可追溯；开场有动作与承诺；问题能兑现 |
| 3. 声画分镜 | [分镜表](templates/storyboard.md)、[素材方案](templates/asset-plan.md)、声音方案、可选 cue、转场 | 对象与事实相符；关系可见；风格和强度符合用途 |
| 4. 质量样段 | 开场＋最难机制镜头＋一次代表转场的真实编码短片 | 核心资产达到最终画质，关键动作与声音真实对齐 |
| 5. 全片制作 | 可编辑工程、统一时间轴、字幕、声音事件、素材记录 | 每章讲清，镜头承接自然，字幕没有空等或抢读 |
| 6. 输出与修复 | 完整视频、对应 QA、修订版本及差异 | 文件、画面、声音、版本身份分别通过检查 |
| 7. 发布包 | 封面、标题简介标签、交付清单、复现说明 | 对外承诺与正文一致；当前平台裁切和文件选取正确 |

按任务需要读取对应参考：

- [故事与证据](references/story-and-evidence.md)：论文转脚本、钩子、问题链、字幕停留、完整叙事示例。
- [用途与风格](references/style-and-purpose.md)：开工询问、独立风格维度、确认与修订边界。
- [参考分析与迁移](references/reference-analysis.md)：8 条参考中的具体方法、时间码与证据限制，新增参考的抽帧和迁移流程。
- [视觉设计](references/visual-direction.md)：设计系统、资产选择、材质和空间、动作配方、转场与穿模检查。
- [模型库与跨对话复用](references/model-library.md)：先发现本地素材，核对结构、部件、大小与许可，再设计镜头；新项目或已有项目如何建立发现入口。
- [音乐与时间](references/music-and-timing.md)：可选音乐、包络与瞬态、结果帧、混音与对齐。
- [制作、检查与修复](references/production-and-qa.md)：可复现实现、渲染预算、最终文件验证、局部修复、交付结构。
- [发布素材](references/publishing.md)：封面构图、平台画幅、标题简介、素材来源与发布包。
- [真实案例与失败修复](references/case-study.md)：《把细菌，变成药》的最终结果、反馈、修正原因与适用边界。
- [可移植工具](references/tools.md)：分析 BGM、检查时间轴、完整解码与抽帧报告的实际命令和局限。

## 开箱验证与项目起步

新建工程时可以把 [Remotion＋Three.js starter](assets/starter/README.md) 复制到用户项目，再按它的说明安装、预览并渲染。不要直接修改已安装 skill 的模板。它是一个约 12 秒的双条件空间动作实验，用来确认环境、运动、声音和导出链路；不是把所有选题自动变成完整视频的固定片头。

包内 [参考音乐](assets/music/README.md) 与 [来源记录](assets/music/profile.json) 保留原技术实验的可选测试输入；不替新片决定选曲。starter 支持自定义文件和显式静音，换音乐后更新分析与事件时刻。模板时间轴 [timeline.json](templates/timeline.json) 是独立结构示例，不是参考音乐或 starter 的固定卡点表。

在真正项目中运行 [tools.md](references/tools.md) 的音乐分析、时间轴检查、最终媒体检查。读报告中的警告并结合画面判断，不为了让脚本变绿而删掉科学条件或把警告关掉。工具无法自动判断机制是否正确、结果是否真的出现在指定帧、提示音是否在听感上突出，这些仍需视觉和声音复核。

相关工具和模板应以仓库的实际说明为准；不要从示例中的案例数值猜测新音乐时刻。即使没有特定图像模型、GPU 或额外 skill，也能用可用工具执行本流程。已有 Remotion 工程优先沿用其锁定版本；需调用其新 API 时查当前官方文档。若已有 Remotion 官方技能，可结合使用；本 skill 不依赖另一个特定 skill 才能理解核心流程。

## 开始制作时先完成这些判断

**叙事**：写出一个具体的观看理由；挑出最能形成可见答案的 3–5 个问题作为起点，而非固定要求。决定哪一幕是最大揭晓，哪些段落需要安静解释。

**素材**：先盘点本地候选，记录每个可见对象与事实的对应关系。合适时复用；对象、年代、结构、部件或视觉效果不适合时，说明原因并选择 2D、改造或新增素材。按链着色不代表链能独立运动，现成模型不代表机制动画已经做好。先把一个代表镜头做到目标完成度，再推广材质和动作。

**声音**：按本片确认选择音乐、旁白、音效或静音。使用音乐时记录实际文件、长度和版本；剪辑、循环、变速后重新分析。检测瞬态不等于已确认的鼓点，参考片混音也不是纯 BGM。

**工程**：项目内归档输入、素材、源代码、输出与 QA；同一帧的状态必须可复现。使用显式随机种子，避免动画依赖真实时钟、播放历史或异步未完成的资源。

**风险镜头**：先测最难解释的全过程。图表计数与曲线共用数据，地图标签跟随正确地点，插镜返回保留主图状态；涉及空间动作时检查孔洞、旋转扫掠、内外结构与接触。具体关系以本次资料为准。

## 完成的定义

每次重要交付或用户反馈后更新 `planning/project-state.md`：正式文件、实际检查、待检查项、用户已确认／待评价、素材与参考入口、下一步。初始化和安装工具提供项目接续入口，详见工具手册。将稳定方法写入参考记录，具体作品的时长、帧率、配色和喜好保持其适用范围；样片、完整成片和通用组件分别记录状态。

无声片的声音项可标不适用；不为检查制造声音峰或强加音乐。参考影片及其音轨不随本包提供，只有可迁移的分析方法；原案例 BGM 单独注明来源与许可范围。

用 [QA 清单](templates/qa-checklist.md) 标明“已检查／未检查／不适用”和证据，不填写未执行的完成状态。完整视频任务交付可播放视频、可编辑工程、最终脚本／字幕、实际使用的声音与事件记录、范围内的封面文案、预览／渲染方法、素材来源和已知限制；仅分镜、分析或局部修订按请求交付相应成果。

如果环境无法实际渲染，明确交付到哪一步、哪条命令或资源阻塞，保留可运行工程；不要把预览链接或“理论可渲染”写成已生成 MP4。用户对作品的喜欢、机器检查通过和平台观看数据是不同证据；不能把任何一项自动写成“保证高留存”。
