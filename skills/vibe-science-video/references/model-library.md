# 模型库、选用判断与跨对话复用

适用于新片、视觉方案重做和新增／替换素材。仅修字幕、声音或文案时不必盘点全库。目标是让已有素材成为可发现、可判断的创作资源；科学对象和本片风格决定是否采用。

## 1. 先发现真实文件

先沿项目 `AGENTS.md` 和状态记录找到已有素材入口。推荐约定为 `assets/models/README.md`＋`inventory.json`，但已有项目使用别的目录时沿用其布局，不擅自移动或覆盖原件。

检查索引、实际模型、来源记录与预览是否一致。有文件无索引时先做盘点；有索引无文件时记录缺失，不能声称已下载。不要假设新对话自动继承旧聊天全文，或安装 skill 后自动拥有作者电脑上的模型。

在项目根目录运行（只用 Python 标准库）：

```sh
python .agents/skills/vibe-science-video/scripts/scan_models.py --project .
```

默认输出报告到终端，也可用 `--output output/model-scan-v1.json` 保存到新文件。已有报告不会覆盖。该工具检查约定目录及索引中的项目内文件，识别 GLB/glTF/OBJ/STL/FBX/Blend，并报告缺失或无效文件；不会下载、改写模型、替你生成已核实的许可。其他自定义目录按项目指引单独检查，不通过全盘搜索猜位置。

GLB 可读检查包括文件头、长度、场景网格实例的三角面和动画／材质信息；可读不代表美术、科学准确或渲染通过。glTF 的外部贴图、压缩扩展和原生软件格式还需在实际导入器里核查。

## 2. 以镜头的知识任务选择模型

对相关候选回答这些问题，写入 `planning/asset-plan.md`，并在分镜中引用素材 ID：

| 判断 | 具体检查 | 如何处理 |
|---|---|---|
| 科学对象是否一致 | 蛋白／物种／构象／器官范围；实验坐标还是造型示意 | 不用相似外形替代不同机制。必要时改造、换模型或改成二维示意 |
| 能否完成本段动作 | 所需对象是否独立，关节／轴／皮肤／动画是否真实存在 | 按链着色常只有一个网格；需拆分时单独安排工作 |
| 画面是否合适 | 轮廓、细节、光照、透明度、遮挡和手机尺寸可读性 | 先看现有预览，再做本片代表镜头；全白模型不一定是缺贴图 |
| 体积和性能是否合适 | 文件字节、场景实例三角面、材质／纹理和同时加载数 | 区分压缩文件大小、GPU 内存和渲染耗时；用目标条件实测 |
| 来源和使用范围是否清楚 | 原作链接、作者、许可、修改、署名 | 未知就记录未知，不能把全部素材统一宣称 MIT 或免版权 |

优先复用合适模型，不要求每片使用 3D。记录关键弃用理由即可，例如“现有细菌仅有光滑外形，本镜头需解释膜孔，因此另做局部结构”。不能为消耗素材改写科学内容。

## 3. 整理成便于接续的库

每个模型保留原件和来源；转换版另存。推荐布局：

```text
assets/models/
  README.md
  inventory.json
  chosen-model/
    model.glb
    source.json
    ATTRIBUTION.txt
output/model-previews/
  chosen-model.mp4
  validation.json
planning/asset-plan.md
```

最小索引条目（示例路径，须替换为真实文件）：

```json
{
  "id": "chosen-model",
  "title": "本片使用的结构",
  "path": "chosen-model/model.glb",
  "sourceRecord": "chosen-model/source.json",
  "sourceUrl": "实际原作页面",
  "license": "按原作核实，未核实时留空",
  "usability": "本片适用镜头",
  "limitations": ["实际已知限制"]
}
```

索引是条目数组；`path` 和 `sourceRecord` 均相对于 `assets/models/`。不要把个人盘符写入共享 skill。`source.json` 可补充下载日期、版本、SHA-256、实际字节、格式、坐标方向／单位、独立部件、动画、转换步骤、署名和已执行验证。未知值不填成默认事实。

原始下载包、转换中间结果和推荐使用版本分开统计。同一器官的两种导出不算两个不同模型；同一共享几何被多个节点使用时，应统计场景实例的绘制量。

## 4. 实际导入与短片验证

1. 按原节点变换加载，确认有限包围盒与方向，在外层设固定缩放和取景。带动画的模型考虑运动范围，避免每帧重新居中造成抖动。
2. 确认贴图／顶点色、独立部件与骨架实际可用。保留原件；需要独立高亮时克隆材质，蒙皮实例复制须保留正确骨架关系。
3. 依照本片已确认风格设置灯光、材质和镜头。白模可以赋予展示材质，并记录这是本地展示改动。
4. 从帧号驱动原作者动画或自制动作，渲染一个覆盖主要角度／动作的小段。素材的整体旋转只是检查外观，不能冒充膜运输、基因剪切或机械工作过程。
5. 完整解码输出，查看开始、中段、最大动作和结束等关键帧；检查裁切、遮挡、透明排序、接触和字幕。按实际覆盖记录“文件检查、选帧目视、连续播放、科学核查、用户评价”。

## 5. 为新对话留下入口

仓库的初始化器和安装器会在项目根 `AGENTS.md` 追加一段简短发现指引，保留已有内容。使用手动安装或升级包的已有项目，可以单独运行：

```sh
python .agents/skills/vibe-science-video/scripts/project_guidance.py --project .
```

该步骤只补项目入口，不移动素材或覆盖现有清单；重复运行不重复追加。若项目有优先级更高的 `AGENTS.override.md`，遵循该项目约定，将相关入口合并到实际生效的指引中，不盲目覆盖。启动新对话时选择项目根目录；其他产品按其指引发现机制配置，或显式要求代理读取本 skill。

接续记录保留模型清单位置、本片选用方案、最新可播放预览、验证范围和待做事项。新项目初始 `inventory.json` 为 `[]`，不把未下载的示例标为已拥有。

## 6. 本次实践提供的选择经验

这些是方法实例，不是包内附赠或自动下载清单：

- [RCSB PDB](https://www.rcsb.org/) 的 DNA、Cas9 等真实坐标适合准确定位，再转换为骨架或表面；显示半径、缺失残基和粗粒化须记录。
- [NIH 3D](https://3d.nih.gov/) 的分子表面可用于整体结构；按链配色不保证链是独立网格。原为打印设计的细菌模型可能只有简单轮廓，需看实际图像。
- [BodyParts3D](https://dbarchive.biosciencedbc.jp/en/bodyparts3d/download.html) 的器官可按组成部分展示；ID、许可、坐标方向和简化程度须连同原件保留。
- [Lukas Ded 的细胞膜](https://sketchfab.com/3d-models/cell-membrane-b3564ec834f84397a3188edab5e5acd9) 是便于观察双层的造型白模；[PDB 2MSC](https://www.rcsb.org/structure/2MSC) 的脂质坐标是另一来源，二者不能互相冒充。
- [Rukh3D 机械臂](https://sketchfab.com/3d-models/animated-robotic-arm-blender-3d-2d3d6519931a4ec180ff9b32a4acb09f) 的原作者骨骼动画，与 [SO-101](https://github.com/TheRobotStudio/SO-ARM100) 的关节节点控制，是不同的复用方式。

访问原作者页面确认当前提供的格式、版本和许可。下载受登录或浏览器阻拦时保留已完成工作，让用户提供正常下载的文件，再检查身份和完整性。不要把网页预览可见当成文件已下载。
