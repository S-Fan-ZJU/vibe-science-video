# 案例：《把细菌，变成药》

本 skill 来源于一条真实制作并经过多轮修订的视频。作者反馈已发布到 B 站和抖音，对最终结果满意，并收到同学好评。本案例提供经过实践的判断方法；未提供平台留存或点击数据，不构成传播效果保证。

## 最终作品与内容范围

| 项目 | 本案例结果 |
|---|---|
| 基础资料 | Gurbatri、Arpaia、Danino，*Engineering bacteria as interactive cancer therapies*，Science，2022，DOI：[10.1126/science.add9667](https://doi.org/10.1126/science.add9667) |
| 观众 | 普通观众 |
| 声音 | 中文字幕、BGM、关键音效，无旁白 |
| 成片长度 | 177.466667 秒，10,648 帧，60 fps |
| 输出 | 3840×2160 母版、1920×1080 播放版 |
| 核心形式 | 连续三维开场、双钥匙条件逻辑、群体裂解、免疫作用、超声开关 |
| 正文字幕 | 43 条 |
| 封面 | 分别构图的 4:3、横版、3:4；早期 9:16 方案另存 |

综述讨论多个系统。视频把它们作为不同设计策略介绍，不应理解为一个菌株同时具备所有能力。锁和钥匙是双条件逻辑的视觉比喻；菌外信号与菌内载荷分色；释放保留与研究策略相符的幸存者；巨噬细胞是吞噬者；超声触发的是所选温控设计，不是把细菌直接炸开。

## 1. 从平淡开场到清楚的问题

早期问题是开头缺少观看动机，选用图片含义也不明确。改进并非只换更“炫”的图片，而是把开头做成连续动作：切除病灶 → 药物作用与身体代价 → “药，能不能自己判断？” → 技术与片名揭晓。

最终前 15 秒包含：

| 时刻 | 动作与作用 |
|---|---|
| 0–3.067 秒 | 手术刀实际切除，让第一画面就有主题与动词 |
| 3.067–6.55 秒 | 药物作用于目标并影响部分正常细胞，建立代价关系 |
| 6.55–9.65 秒 | 让问题落到身体承受，而非抽象技术口号 |
| 9.65–12.733 秒 | 动作收束，提出能否按环境作出响应的问题 |
| 12.733 秒 | 细菌主体与大标题在主 cue 揭晓 |

可迁移的是“相关对象＋真实动作＋值得回答的问题”，不是这些秒数或医疗痛苦主题。

## 2. “每句停太久”不是“每句字太多”

用户明确纠正过这个理解。最终压缩的是读完后的空等、慢入场以及没有新信息的段落，保留必要机制。字幕单条约 3.07–5.38 秒、最高约 5.70 中文字／秒，只是这个版本的统计。

教训：收到“节奏慢”时先看观众当时有什么任务。既没有阅读任务，也没有观察任务，通常应该推进；需要观察失败／成功对照时，时间本身有解释价值。

## 3. “03 没卡上”的两个原因

早期释放点约在 100.359 秒，邻近声音较弱，同时画面从开始运动到清楚展开还有约 0.3 秒。数学上靠近起音，观看上却没有击中。

修订选用约 98.731 秒的更强瞬态，并让第 5924 帧（98.733 秒）已经出现膜分离与载荷跨出。不是把全片统一提前某个偏移，而是重新选择声音事件，并把缓动准备放在结果之前。

案例成片主要结果帧：

| 结果 | 时间 | 帧号 |
|---|---:|---:|
| 片名揭晓 | 12.733 秒 | 764 |
| 双条件开门 | 69.433 秒 | 4166 |
| 群体裂解与载荷冲出 | 98.733 秒 | 5924 |
| 免疫抑制解除 | 121.050 秒 | 7263 |
| 温控生产启动 | 145.517 秒 | 8731 |
| 片名收束 | 172.667 秒 | 10360 |

这些属于**剪辑后的成片音轨**，不能直接用于包内原始 BGM，更不能用于自定义音乐。

## 4. 从示意 demo 到可观察的空间动作

用户要求图画、文字、转场和动作达到可发布的完成度。解决方向包括：主体轮廓与材质、连续三维开场、清楚的微观内外结构、立体双钥匙和实际开合、薄膜包裹、与场景对象相接的转场。

双条件逻辑尤其需要“单条件失败 → 另一条件单独失败 → 共同满足成功”的对照。只有两个发光标签或一个弹出的“AND”字样，信息存在但视觉解释不充分。

这不意味着下一条视频必须都用三维。可以用 2D 很清楚地解释数量或公式；关键是让画面承担概念，而不是把图形当字幕背景。

## 5. 30 秒与 67 秒的问题如何修

| 问题 | 实际修改 | 泛化方法 |
|---|---|---|
| 细胞与血管相交 | 细胞交错排布，血管移至更深层 | 检查完整模型范围和全部运动，不只看中心点 |
| 透明膜覆盖前方对象 | 按对象组管理远近，保留内部膜层次 | 几何相交和透明排序分开诊断 |
| 钥匙穿锁孔 | 实心套筒改真实空心孔，给齿部扫掠留空间，调整轴线 | 检查插入、旋转、开门的整段动作 |
| 局部主体异常变暗 | 对比 PNG、JPEG、短片、中间帧与最终 H264 | 不把未复现的原因猜测写成结论，也不盲目全片提亮 |

本案例钥匙动作检查覆盖 1,289 个输出帧，孔壁保守净距约 0.053 个场景单位；这些是特定几何和单位体系下的值。不能照抄成其他模型的安全阈值，也不能把逐帧顶点采样称为连续碰撞证明。

局部暗化的确切根因未确定。修正版的多个渲染阶段比较一致，足以支持交付检查，但不足以宣称“某个 GPU 参数就是根因”。

## 6. 提示音为何听不清

独立音效可听，不代表放进音乐后仍突出。最终保留 20 个事件时刻，对 13 个铃声提高 8 dB，并在附近把 BGM 降低 3 dB。衰减约 35 ms 进入、200 ms 保持、300 ms 恢复；重叠窗口不反复叠加。

WAV 样本峰值约 −1.90 dBFS，4 倍过采样真峰值估计约 −1.67 dBFS；编码后的 AAC 也重新解码检查。六个声音窗口在 8 kHz 分析网格内测得 0 ms 偏移。这些支持电平和同步检查，不是 LUFS 测量，也不替代设备试听。

可迁移的是“在真实混音中比较、让关键声音露出来、编码后再检验”，不是“所有铃声固定加 8 dB”。

## 7. 修图要不要重渲全片

这次几何问题补渲了 25–77.9 秒，但最终只替换 25–73.733 秒，即第 1500–4423 帧，共 2924 帧。选择全遮挡转场处接回原片，避免接缝亮度差异。其他 7724 帧的视频编码内容保留。

这依赖编码参数、真实 IDR 边界、时间戳和完整解码验证。若新项目没有这些工具或条件，不能简单套用相同拼接方法。只改音效时则无需重新计算三维画面，可以保留视频流换音轨。

## 8. 哪些经验应成为下一条的起点

| 反馈 | 提前防止的方法 |
|---|---|
| 开头不够抓人 | 在建模前写清前 15 秒对象、动作、冲突和揭晓 |
| 画面像 demo | 先完成一个最终质量代表镜头，再扩展全片 |
| 动效死板 | 按动作语义拆阶段，用失败／成功对照解释原因 |
| 字幕停留过长 | 标注每条的阅读和观察任务，删掉无任务空等 |
| 卡点无力 | 检查所选声音强度和可见结果帧，别只看起始时间 |
| 转场生硬 | 分镜阶段设计承接对象、交换帧和下一场落点 |
| 叮咚太轻 | 在真实音乐中试听，并检查相对响度与编码峰值 |
| 穿模／异常暗化 | 检查整段动作和实际编码结果，保留不确定根因 |
| 封面比例反复改 | 正片画幅与各平台封面画幅分开列出并核验像素 |

将这些经验写入制作过程，能减少可避免的返工。新选题仍需要新的事实、镜头、音乐选择和观看判断。
