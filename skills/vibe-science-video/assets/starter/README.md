# 12 秒动作实验：双钥匙 / 一个答案

这是独立可运行的 **3D 动作与卡点实验**，用于验证环境、构图、真实孔洞、动作预备和结果帧同步。它不是替换几个文字就能发布的完整科普片；新主题仍须完成事实核查、叙事和分镜设计。它和 `docs/media/showcase.mp4` 的完整作品案例不是同一个视频。

## 第一次运行

需要 Node.js 22.13+、npm 和可用的浏览器渲染环境。保留技能目录内 `assets/starter` 与 `assets/music` 的相邻关系。仓库初始化工具生成的 `项目/film` ＋ `项目/assets/music` 布局也能直接运行默认 `setup`。把 starter 单独复制到其他位置时，可以用 `--bgm` 指向任意本地音乐。

```sh
npm ci
npm run setup
npm run check
npm run preview
npm run render
```

`setup` 默认导入包内参考 BGM 并生成原创短提示音，也检查存在音轨以及截取后至少覆盖 12 秒。过短的自定义音乐会报错，需有意剪辑/延长后再导入。音频配置缺失时，预览和渲染会明确报错；不会把缺声当成功。`render` 每次创建独立的时间戳与随机编号输出目录，旧输出保留。预览及导出均可能在首次使用时下载 Chrome Headless Shell。网络不可用时先安装兼容浏览器，并根据 [Remotion 浏览器文档](https://www.remotion.dev/docs/cli/browser) 配置。

```sh
# 自定义 BGM；带空格路径必须加引号
npm run setup -- --bgm "path/to/my-music.wav" --trim 0 --force
# 明确选择静音的视觉检查
npm run setup -- --silent --force
# 只导出一个关键帧；可附加 --frame=431 等
npm run still
# 先快速验证低分辨率的 2 秒（帧区间两端都包含）
npm run render -- --scale=0.5 --frames=390-509
```

Windows 如果软件渲染过慢，可在确认 ANGLE 可用后执行 `$env:REMOTION_GL='angle'`；macOS/Linux 不应照抄这个选择。默认不强制某块 GPU。进一步配置见 [Remotion CLI](https://www.remotion.dev/docs/cli/render)。

## 改哪里

| 文件 | 用途 |
|---|---|
| `src/Root.tsx` | 画幅、帧率、时长、最终两行标题 |
| `src/timing.ts` | 插入、旋转、预备、激活、转场的时间 |
| `src/Scene.tsx` | 立体结构、灯光、独立文字轨、声音轨 |
| `src/geometry.mjs` | 孔径、齿宽等几何尺寸；检查脚本共用 |
| `src/audio-config.json` | setup 生成的音频相对路径、音量、截取起点、音频哈希 |

默认激活时间是 **7.20 秒，第 432 帧（60 fps）**。灯光从这一帧直接进入激活状态，扩散动效随后展开。提示音从同一帧起播，合成音的短起音约 4 ms。音乐默认从 5.533333 秒截取，借用了原案例首段的音乐结构；这是具体示例，不是任意音乐的通用卡点。替换/剪辑 BGM 后必须重新分析和听看核验，不能保留这组时间就声称精准卡点。

时间轴中的文字轨、场景轨、音频轨可以单独选择；3D 模型和粒子是程序生成的，需要改源码而非逐个拖拽物体。文字优先使用机器上的 Noto Sans CJK SC、微软雅黑或苹方；没有中文字体时先安装许可允许的中文字体，检查实际输出。包内不附带系统字体。

### 扩展成你自己的选题时

本实验的工程假设是 12 秒、1920×1080、60 fps；改变成片规格时，不能只改 `Root.tsx`：

- 竖屏需要重新布局 `Scene.tsx` 的固定 1920×1080 文字层，调整镜头和主体位置，不用整体缩小代替排版。
- 延长时长时，同步调整 `Scene.tsx` 中按 12 秒计算的音乐淡出，以及 `scripts/setup.mjs` 的 12 秒音轨长度检查；否则可能出现尾部缺声或非法负音量。
- 改帧率后，以秒为依据重新量化事件帧；`scripts/run.mjs` 的默认静帧 432 仅适用原实验。用 `npm run still -- --frame=你的帧号` 验证新结果帧。
- 改 Composition 名称时，同步修改 `scripts/run.mjs` 的 `MotionLab` 目标。新题材可以重写场景和事件表，不必勉强保留双钥匙结构。
- 新主题先跑时间轴、类型检查和关键帧，再实际导出小段；音乐导入成功不代表字幕、声音和场景已经自动适配。

## 验收实验

1. 看 0、2.9、5.9、7.183、7.20、7.45、9.3、10.3 秒：钥匙先接近再插入和旋转；只有双条件齐备后输出亮起。
2. 检查 431/432/433 帧：不能把缓动起点误称为观众已经看到的结果。
3. `npm run check` 检查类型与钥匙旋转包络；它不证明所有三角面无穿模，也不代替完整播放。
4. 最终 MP4 确认音轨、时间戳、分辨率和字幕裁切；手机小屏检查文字，耳机及普通扬声器听提示音。
5. 新主题用自己的机制模型替换比喻。不要把“两个条件”自行解释成同一篇论文支持的癌症治疗事实。

维护模板时可运行 `npm run test:setup`：在 `out/` 内新建隔离目录，实际验证初始化项目的默认音乐路径、重复导入拒绝、短音乐拒绝、失败时保留配置和显式静音。不会改写正在使用的音频配置。

本次发布前已完成：锁定依赖安装、类型与几何检查、Studio 预览，以及 960×540/60 fps 的完整 12 秒测试导出。测试导出完整解码 720 帧，音轨存在，时间戳检查通过；抽查 12 个画面及激活相邻帧。第 432 帧可见点亮，提示音在解码音频中定位为 7.200 秒。此验证不等于所有设备性能一致，也不替代新作品的完整听看。

导出包装脚本使用独立新目录避免覆盖旧文件，同时规避某些文件系统不支持硬链接导致的 Fast Start 收尾失败。若直接绕过包装脚本使用 Remotion CLI，请自己指定新输出路径；配置中的 overwrite 开启仅用于这个收尾兼容方案。

使用的运行库遵守各自许可；本目录源码许可不覆盖 Remotion 的产品许可，也不覆盖参考 BGM。参见仓库根目录的第三方资源说明。
