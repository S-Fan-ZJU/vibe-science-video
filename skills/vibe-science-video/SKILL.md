# Vibe Science Video

把知识做成观众愿意看完、能看懂因果、经得起实际播放的动画。目标是第一轮就建立接近发布标准的质量基线，再用有证据的检查修正问题。不要承诺任意主题都能一次生成成功，也不要把生成源代码当成已经交付视频。

## 先判断任务处于哪里

- **新作**：读取 [故事与证据](references/story-and-evidence.md)、[视觉设计](references/visual-direction.md)，建立 brief、事实表和分镜。
- **接着做已有项目**：先找当前交付清单、最终音轨、时间轴和用户最后反馈；保留满意镜头与旧输出，不用历史草案覆盖正式版。
- **修改指定问题**：读取 [制作、检查与修复](references/production-and-qa.md) 的修复部分，记录时间点、对象、现象，决定换音轨、补渲还是重排全片。
- **只做封面或文案**：读取 [发布素材](references/publishing.md)，不启动不必要的视频重做。

制作新片、重新定视觉方案或新增／替换画面素材时，先检查项目现有模型库，再决定建模或下载。读取项目 `assets/models/README.md`、`inventory.json` 和已有预览；没有清单时用 [模型复用流程](references/model-library.md) 中的只读盘点工具找真实文件。按科学对象、镜头需要与已确认风格选择复用，并在 [素材方案](templates/asset-plan.md) 记录文件和取舍。仅改字幕、混音或发布文案时，无需重扫模型库。

用户的当次选择高于以下默认值：普通观众；中文字幕＋BGM＋关键音效，无旁白；时长由解释需要决定，可从 2–4 分钟规划；横屏 16:9；预览用较低分辨率，最终可交付 4K60 母版和 1080p60 播放版。预算、硬件或题材不适合时提出具体取舍，不把 4K、60 fps 或 3D 当成质量的替代物。

只补问无法从现有资料取得、且会改变结果的信息。已有主题就不要强制重新选题。用户要求先看样片时，在样片处交付；用户授权连续完成时，经过内部质量检查继续做完，不逐阶段重复请求许可。制作授权不自动包含公开发布或修改外部账号。

## 这套流程的核心约束

1. **第一眼就有意义。** 第一秒出现与主题直接相关的对象，前几秒发生明确动作。用人的处境、反直觉现象或可观察矛盾提出问题，技术名称随后出现。
2. **每段推进一个理解。** 以“问题 → 条件变化 → 对象行为 → 可见结果”解释机制；回答之后再引出下一问。不能用一串疑问替代答案。
3. **视觉比喻不能偷换机制。** 事实表记录对象、条件、因果、出处、简化方式和不能画出的含义。不同研究策略用章节或措辞区分，不能拼成一个万能系统。
4. **爆点对准结果帧。** 音乐攻击点到来时，观众已经看见接触、开门、膜分离或状态点亮，而不是动画刚开始缓慢移动。
5. **紧凑不等于删字。** 先去掉慢入场和读完后的空等；复杂动作仍需观察时间。字幕、动作、SFX 从同一时间轴导出。
6. **精致服务于理解。** 清晰主体、材质、层次、方向和可见接触优先于无关粒子。需要前后遮挡、插入、包裹的机制，应使用可验证的空间结构。
7. **转场也是分镜。** 明确上一场对象、遮挡或形状接续、交换帧、下一场落点。不要等全片完成后统一加淡入淡出。
8. **检查最终文件。** Studio、PNG、编码 MP4 和上传预览可能不同。完整解码、选帧检查、连续播放与实际试听分别记录，不能相互冒充。

## 可执行的交付流程

| 阶段 | 必须产生的可检查成果 | 下一步的判断依据 |
|---|---|---|
| 1. 接收输入 | [brief](templates/brief.md)：问题、观众、资料、声音、画幅、范围、项目根目录 | 观众看完理解什么；是否已有明确来源和必要素材 |
| 2. 内容与叙事 | [事实表](templates/fact-ledger.md)、一句话主线、问题链、前 15 秒设计 | 关键结论可追溯；开场有动作与承诺；问题能兑现 |
| 3. 声画分镜 | [分镜表](templates/storyboard.md)、[素材方案](templates/asset-plan.md)、最终 BGM 身份、候选 cue、转场方案 | 模型与科学结构相符；关键动词可见；强弱层次明确 |
| 4. 质量样段 | 开场＋最难机制镜头＋一次代表转场的真实编码短片 | 核心资产达到最终画质，关键动作与声音真实对齐 |
| 5. 全片制作 | 可编辑工程、统一时间轴、字幕、声音事件、素材记录 | 每章讲清，镜头承接自然，字幕没有空等或抢读 |
| 6. 输出与修复 | 完整视频、对应 QA、修订版本及差异 | 文件、画面、声音、版本身份分别通过检查 |
| 7. 发布包 | 封面、标题简介标签、交付清单、复现说明 | 对外承诺与正文一致；当前平台裁切和文件选取正确 |

按任务需要读取对应参考：

- [故事与证据](references/story-and-evidence.md)：论文转脚本、钩子、问题链、字幕停留、完整叙事示例。
- [视觉设计](references/visual-direction.md)：设计系统、资产选择、材质和空间、动作配方、转场与穿模检查。
- [模型库与跨对话复用](references/model-library.md)：先发现本地素材，核对结构、部件、大小与许可，再设计镜头；新项目或已有项目如何建立发现入口。
- [音乐与时间](references/music-and-timing.md)：默认案例 BGM、自定义替换、拍点验证、音效和混音、音画对齐。
- [制作、检查与修复](references/production-and-qa.md)：可复现实现、渲染预算、最终文件验证、局部修复、交付结构。
- [发布素材](references/publishing.md)：封面构图、平台画幅、标题简介、素材来源与发布包。
- [真实案例与失败修复](references/case-study.md)：《把细菌，变成药》的最终结果、反馈、修正原因与适用边界。
- [可移植工具](references/tools.md)：分析 BGM、检查时间轴、完整解码与抽帧报告的实际命令和局限。

## 开箱验证与项目起步

新建工程时可以把 [Remotion＋Three.js starter](assets/starter/README.md) 复制到用户项目，再按它的说明安装、预览并渲染。不要直接修改已安装 skill 的模板。它是一个约 12 秒的双条件空间动作实验，用来确认环境、运动、声音和导出链路；不是把所有选题自动变成完整视频的固定片头。

包内 [参考 BGM](assets/music/reference-bgm.m4a) 与 [来源／分析资料](assets/music/profile.json) 提供默认音乐输入；已有用户音乐优先使用。starter 支持自定义文件，替换后要更新分析与事件时刻。模板时间轴 [timeline.json](templates/timeline.json) 是独立结构示例，不是参考音乐或 starter 的固定卡点表。

在真正项目中运行 [tools.md](references/tools.md) 的音乐分析、时间轴检查、最终媒体检查。读报告中的警告并结合画面判断，不为了让脚本变绿而删掉科学条件或把警告关掉。工具无法自动判断机制是否正确、结果是否真的出现在指定帧、提示音是否在听感上突出，这些仍需视觉和声音复核。

相关工具和模板应以仓库的实际说明为准；不要从示例中的案例数值猜测新音乐时刻。即使没有特定图像模型、GPU 或额外 skill，也能用可用工具执行本流程。已有 Remotion 工程优先沿用其锁定版本；需调用其新 API 时查当前官方文档。若已有 Remotion 官方技能，可结合使用；本 skill 不依赖另一个特定 skill 才能理解核心流程。

## 开始制作时先完成这些判断

**叙事**：写出一个具体的观看理由；挑出最能形成可见答案的 3–5 个问题作为起点，而非固定要求。决定哪一幕是最大揭晓，哪些段落需要安静解释。

**素材**：先盘点本地候选，记录每个可见对象与事实的对应关系。合适时复用；科学对象不符、缺少必要部件或视觉效果不适合时，说明原因并选择 2D、改造或新增素材。按链着色不代表链能独立运动，现成模型不代表机制动画已经做好。先把一个代表镜头做到目标完成度，再推广材质和动作。

**音乐**：可以选案例 BGM，也可以用用户自定义音轨。先识别实际输入文件、长度和版本；剪辑、循环、变速之后对最终音乐重做分析。拍点检测只是候选，需要波形和实际试听确认。

**工程**：项目内归档输入、素材、源代码、输出与 QA；同一帧的状态必须可复现。使用显式随机种子，避免动画依赖真实时钟、播放历史或异步未完成的资源。

**风险镜头**：先测最难动作的全过程。双钥匙必须有真实孔洞和扫掠间隙；释放先有内部载荷再分离；包裹应由吞噬者向目标连续闭合。具体机制以本次资料为准。

## 完成的定义

用 [QA 清单](templates/qa-checklist.md) 逐项标明“已检查／未检查／不适用”和证据，不填写未执行的完成状态。最终交付至少包括可播放视频、可编辑工程、最终脚本／字幕、音乐与 cue 记录、封面与文案（在任务范围内）、可用的预览／渲染方法、素材来源和已知限制。

如果环境无法实际渲染，明确交付到哪一步、哪条命令或资源阻塞，保留可运行工程；不要把预览链接或“理论可渲染”写成已生成 MP4。用户对作品的喜欢、机器检查通过和平台观看数据是不同证据；不能把任何一项自动写成“保证高留存”。
